# 回放翻译整会话第五迭代：进度口径改按提问数 + 加载态统一缓转圆环

前序：`782f3180-7153-4e56-8eb9-94c7ccc44830`（按文本量切块 + 3 路并发，MR !1133 / !1127）、`64041ba0-ab9a-437b-9926-14e657b5662e`（模型单次容量上限证据与四层分批）。本篇只记这轮的两个 UI 口径修正与其交付状态。

## 用户反馈（7 个提问的会话）

1. 点「Translate all」显示 `0/2`，但会话里有 7 个提问——分母是**传输块数**，用户误读成提问数。
2. 「加载动画改成转圈，别转那么快；数据加载的特效也改成转圈，像鸿蒙那样」。

## 修正一：进度单位从"块"换成"提问数"

- 原来 `allProgress.value = `Translating ${doneChunks}/${totalChunks}``，分母是 8000 字符累计切出的块数；7 个提问的文本正好塞进 2 块，于是显示 0/2。
- 改为按**提问数**报：分母取 `sessionTurnIds.length`，形如 `0/7 → 2/7 → 4/7 → 7/7`；没有可翻文本的轮次直接计入完成（`doneTurns = totalTurns - plans.length` 起算），不会卡在 6/7。
- 教训：**进度分母必须是用户能感知的业务单位（提问数），内部传输块数属于实现细节，暴露出来就会被误读**。

## 修正二：分块参数再收紧

- `CHUNK_CHARS` 8000 → **6000**，单块最多 4 → **2** 轮；7 个提问约切 4 块，跳变更密，首块回流更快。
- 代价：请求数略增（并发 3 路已抵消）。

## 修正三：加载态统一为缓转圆环

| 位置 | 原来 | 现在 |
|---|---|---|
| `src/views/Setting/reports/history-replay/HistoryChatPanel.vue`（`.translate-dots` 三点起伏，约 928–962 行） | 3 个 4px 点 1.25s 起伏 | `.translate-spinner` 12px 细环，1.3~1.35s/圈，取 `currentColor`（主按钮白环、次级按钮紫环） |
| `src/views/Setting/reports/user-logs/components/ui/LoadingRows.vue` | 骨架条 + `ms-sheen` 扫光 | 居中 30px 细环（3px 环宽），保留 `rows`/`variant` 原占位高度 |
| `src/views/Setting/reports/usage-issue-feedback/components/LoadingRows.vue` | 同构骨架条 | 同上 |

- 两份 `LoadingRows.vue` 是"同构"实现（注释即写「与 user-logs 的 LoadingRows 同构」），改动画要**两处一起改**，否则 user-logs 各视图与 Issue & Request 页观感不一致。
- 「轮子飞转」的根因是默认 spinner 1s/圈，压到 1.3s/圈即显柔和;保留占位高度是为了避免列表在骨架与环之间切换时抖动。
- 可选的下一步（已向用户提出、未实施）：鸿蒙式带渐隐尾巴的 `conic-gradient` + 遮罩弧，更柔和但跨浏览器渲染有差异。
