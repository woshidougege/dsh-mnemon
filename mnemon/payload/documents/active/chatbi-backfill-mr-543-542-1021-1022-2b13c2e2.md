## 1. 用户确认的评审口径（业务判定规则）

用户原话要求（生产现象 → 期望）：最终状态为失败的都该判 Wrong；**没展示数据**的返回错误；**无权限**的返回成功；**其他步骤失败但已出数据**的显示成功。

## 2. 生产规则表实况（`public.ssg_chatbi_question_review_setting`，id=1）

`auto_review_enabled=t`、`auto_wrong_timeout=t`、`auto_wrong_failed=t`、`auto_wrong_no_result=t`、`auto_wrong_needs_input=f`（更新人 renxp4，2026-11-14 00:38:07）。

**规则配置本身没有问题**，漏评审是代码多了一行排除条件。

## 3. 根因与 653 条逐条复算

生产 `ssg_chatbi_event` 失败轮次 969 = backfill 653 + 实时 316。`ChatbiQuestionAutoReviewMapper.java:83` 的
`AND COALESCE(ssg_chatbi_event.properties ->> 'source', '') <> 'backfill'`
把 653 条整体跳过，永久停在 Pending（用户举例的 kmurphy2 / id=97377，`properties.source='backfill'`）。

按候选 SQL 逐条复算 653 条：

| 分类 | 条数 | 是否该判错 |
|---|---|---|
| 巡检数据（session 命中 `public.ssg_ai_probe_run`） | 193 | 否 |
| 有 Smart Data 结果卡（页面 Final result 算 Success） | 6 | 否 |
| **实际应判 Wrong** | **454** | 是 |

653 条中 timeout 207 条；`query_id` 缺失 0 条（回填行把 query_id 放在 properties 里，靠 `TURN_ID_SQL` 兜住）。修复后候选数 454，与 653−193−6 吻合。

## 5. 用户三条口径的核对结果（代码当时已符合）

- **无权限返回成功**：`LUDP_PERMISSION_SQL`（`ChatbiEventQueryMapper.java:444-449`，execute 工具 succeeded 但业务返回 `ludp_permission_denied`）识别出生产 33 条，`status` 全为 success、页面显示 Success；候选 SQL 用 `AND NOT LUDP_PERMISSION_SQL` 显式不判错。
- **没展示数据返回错误**：`no_result` / `empty` 走 `auto_wrong_no_result`（已开），全库此类共 2 条（1 empty + 1 no_result），覆盖完整。
- **步骤失败但出数据 → 成功**：靠 `SMART_DATA_DISPLAY_SQL`（:428-435），审计 `agent.tool_audit_logs` 里存在 `contract=smart_data_query_result/v1` + `status=success` 即排除；命中回填 6 条、实时 34 条，与页面 Final result 同源。

## 6. 判定常量速查（改候选条件时必须与之同源）

均在 `smartop-service/admin/src/main/java/com/lenovo/admin/chatbi/dao/ChatbiEventQueryMapper.java`：

- `AUDIT_SESSION_ID_SQL`（:407-409）优先 `properties.upstream_session_id`（AskPreview 的 Spark 真实会话），回退 `session_id`。
- `TURN_ID_SQL`（:416-418）`query_id` → `properties.query_id` → 空串；补漏写入只把 query_id 放 properties，只看列会匹配不到审计。
- `SMART_DATA_DISPLAY_SQL`（:428-435）tool_name ∈ (`execute_compiled_query`,`execute_sql`,`finalize_query_result`)，`output_summary` 正则匹配 contract + status=success。**不能用 failed_step=finalize_query_result 代替**：finalize 只是可选可视化收尾，查询成功后 finalize 失败前端仍保留结果卡。
- `FINAL_SUCCESS_SQL`（:458-461）= status/answer_status=success **或** 有结果卡；「success 但没结果卡」也算成功（知识问答、PBI 推荐不渲染数据卡）。
- `PROBE_RUN_EXCLUDED_SQL`（:471-473）以 `ssg_ai_probe_run.session_id` 为准，不能只看 `properties.trigger='probe'`（2026-10 后新巡检链路不再写 trigger）；生产 probe_run 合计 4127。
- 归因 tag 映射：`failed_reason/status=timeout` → OTHER；`failed_step=route_report` → WRONG_REPORT；`revise_query`/`resolve_plan` → DEFINITION_MISMATCH；`finalize_query_result` → DISPLAY_ERROR；其余 OTHER。
