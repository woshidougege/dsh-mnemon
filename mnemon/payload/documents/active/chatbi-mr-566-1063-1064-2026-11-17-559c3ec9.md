## 2. 设计决策与理由

**导出（评审模板）**
- 复用既有导出入口：`POST /export` 增 `exportType=review-template`（默认仍为 full report），筛选口径与「问数记录」完全一致，避免两套过滤逻辑漂移。
- 单表 11 列：Session ID / Turn key / Time / User / Question / Final result / Failure category / Review status / Attribution tag / Remark / Review source；文件名带 `(Review template)` 后缀（`ExportFileNames`）。
- 内存：分页 500 行 + SXSSF 流式写，不把结果集堆在内存里（用户明确要求低内存）。

**导入（新接口 `POST /queries/review/import`）**
- **只写与库里不同的行，未改的行跳过** —— 因此「导出全部再导回来」是安全的，不会冲掉别人刚做的评审；这是方案的核心安全属性。
- 写入口径与人审保存一致：`review_source=HUMAN` + 评审流水，reviewer 取当前登录人。
- 两阶段：`dryRun` 预检只读，真正写库前再弹一次确认，列清「会覆盖多少条人工结论」，用户点才覆盖（保护人工结论）。
- 新判 Wrong 的行二选一：立即建单（复用已有台账去重）或交给每小时兜底任务。
- 单次变更 > 2000 行直接拒绝并提示拆批（护栏）。
- 内存：POI 事件模型 SAX 逐行解析，不在内存建整本工作簿；每 400 行一批做查询比对与写入。
- **本次没有新迁移**，只写现有两张表的既有结构。

**前端**
- 问数记录页签的导出弹窗加 `Export type`：Full report（默认）/ Review template。
- 顶部新增 `Import reviews`，三步：选文件 → `Check file`（dryRun 预检）→ 确认执行；预检摘要给出总行数、会改多少行、覆盖多少条自动/人工结论、新判 Wrong 与 Not applicable 各多少；明细表 Before→After+备注（前 200 条）、跳过原因表（前 100 条）。
- 列表刷新用 `refreshTick` ref（`index.vue:99`、`:181-216`、`:340-345`；`DetailModal` 的 `@review-saved="onReviewSaved"` 在 `index.vue:606`）。

## 5. 过程中的坑（可复用）

- PowerShell `-File` 相对路径按错误 cwd 解析会报 `The argument '.tmp\create-mr.ps1' ... does not exist`：跨 worktree 调脚本一律用绝对路径。
- GitLab API 建/改 MR 时 `description` 用命令行内联会被判 `{"error":"description is invalid"}`（HTTP 400，中文/长文本）：改为从 UTF-8 文件读（`Get-Content -Raw -Encoding UTF8`）并按 UTF8 字节提交即成功（实测 desc 长度 1308 正常）。
- `run_code` 里不能用静态 `import` 语句（`Import is not allowed here`），要用动态 `await import(...)`。
- 大仓库跑 `vue-tsc --build` 等命令易超 30s 工具超时，改后台 job + `job_output` 取结果。
