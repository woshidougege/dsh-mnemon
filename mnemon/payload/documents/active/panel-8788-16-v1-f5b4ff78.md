# PANEL 接管 8788：账号池迁移、切换脚本与路由契约差异

对象：本机把 `http://localhost:8788` 的后端从 HUB（Python 便携版）换成 PANEL（Go 单二进制 `wb2api.exe`，位于 `C:\\Users\\63588\\Desktop\\WorkBuddy-Panel`），目标是对 DSH 做到**零改动**（baseURL 与 api_key 都保持原值）。

关联文档：
- `00bd0694-cd83-4184-924d-e1517a8a6097`：PANEL 的媒体能力真机实测、`/mcp` 工具清单、「积分 0」误判根因（`schedule.balance_refresh_enabled` 关着导致 `credits` 从未采样）。本文不重复这些内容。
- `a33b2a00-83e9-4029-b9c7-ac52472c9708`：HUB 与 PANEL 的检索通道对比、账号格式迁移成本（`auths/` vs `accounts/*.json`）。
- `c28e03c1-9f82-401e-aae7-bea1cd218808`：PANEL 部署形态与 auth 文件名 glob 等踩坑。

## 1. 为什么必须尽快切（不是可选项）

HUB 与 PANEL **同时持有同一批账号**时，两边都会定期刷新 refresh_token，谁先刷谁把对方的作废。放置不管的结果是两边逐渐都出现「token 失效」的账号。所以账号迁移完成后必须立刻停掉旧端，不能长期双跑。

## 2. 账号迁移结果

| 项 | 结果 |
|---|---|
| 源文件 | 21 个，其中 **16 个有效**，5 个空文件跳过 |
| 转换 | `converted=16 skipped=5` |
| PANEL 入池 | `reload` 后 `pool=16`、`parse_errors=0`、`added=15`（第 16 个是先前的测试号） |
| 模型数 | 22 → **49**（多账号合并出 cn/global 两个域池） |
| 对话验证 | `glm-5.3-flash` 连续压测两次 `ok`，且换号后仍正常 |

一条无害警告：某个国际版号拉 `/v3/config` 返回 500（enterprise 端点），PANEL 自动降级（`global models: enterprise endpoint failed (v3/config only)`），不影响使用。

## 3. 脚本化切换（关键做法）

**做法**：把切换写成独立脚本在后台执行，脚本自己在启动前 sleep 数秒等待当前回复结束，然后「停 HUB → 释放 8788 → 改 PANEL `listen` → 起 PANEL → 自检」。这样即使 Agent 的会话在端口切换瞬间断掉，操作也能跑完；事后读 `switch.log` 即可判断结果。

实测时间线（`switch.log` 原文）：

```
[17:27:08] ===== switch start, waiting 6s for the reply to finish =====
[17:27:14] stopping HUB...
[17:27:14]   kill hub pid=26748
[17:27:22]   port 8788 free=True
[17:27:22]   kill panel pid=55044
[17:27:24] config listen -> 127.0.0.1:8788
[17:27:24] panel started pid=39452
[17:27:27] SWITCH OK: panel now serves 8788
```

验证：`8788 LISTEN pid=39452 name=wb2api`、`8789 no listener`。

**自检坑**：PANEL **没有 `/health` 端点**（`/health` 返回 404）。用 health 探存活会误判失败，应改探 `POST /v1/chat/completions` 或 `GET /v1/models`。

## 4. 路由契约差异（HUB → PANEL，实测）

| 差异 | HUB | PANEL | 处理 |
|---|---|---|---|
| 路径前缀 | 接受裸 `/responses` | **必须带 `/v1`**：`/responses` → 404，`/v1/responses` → 200 | DSH 的 `baseURL` 必须写成 `http://localhost:8788/v1` |
| 模型 id | 裸名 | `/v1/models` 的 49 个全部带域前缀 `cn:` / `global:`；裸名仍回 200（PANEL 有默认域兜底，默认走 cn） | 显式带前缀；`cn:`/`global:` 是两个独立域名池（国内号 / 国际号），前缀决定走哪个池 |
| `/v1/search`、`/v1/fetch` | 404（没有） | 有：search 回 5 条结果（字段 `query,type,provider,results,total_results,response_time_ms`），fetch 回 `content,content_length,content_type,context,status_code,title,truncated,url` | 可把 `web-deepseek-api` 的 `searchBaseURL`/`fetchBaseURL` 指到 `http://localhost:8788/v1`，替代失效的 key |
| `/mcp` | 404 | 5 个工具：`list_generation_models, generate_image, edit_image, generate_video, get_video_task` | 媒体能力走这条 |

域池划分的依据：`cn:*` 与 `global:*` 模型名并列出现在 `/v1/models` 里（如 `cn:glm-5.3` 与 `global:glm-5.3` 各自独立），说明同一上游模型在国内外两套账号池各有条目。
