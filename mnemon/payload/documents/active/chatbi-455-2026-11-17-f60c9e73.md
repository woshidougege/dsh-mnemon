# ChatBI 生产运行时核对：自动评审“不自动”、无权限不进候选、建单开关打开后的历史批量风险

日期 2026-11-17（生产核对时点 09:44 CST）。本文是对既有落地文档的运行时补充与一处错误结论修正，与 cc5d103b-628e-4216-a1a6-08ef73e07f46（53s 超时定位 + 建单落地 MR !559/!1054/!1055）配套阅读：那份文档记录“做什么、怎么改”，本文记录“上线后生产实际怎么跑、哪里和预期不一致”。

## 一、自动评审没有调度器，只能人点按钮

生产库 ssg_chatbi_question_review_setting（id=1）开关全是开的（auto_review_enabled=t、auto_wrong_timeout=t、auto_wrong_failed=t、auto_wrong_no_result=t、auto_wrong_needs_input=f，updated_by=renxp4），但 com.lenovo.admin.chatbi 包下只有两个 @Scheduled，都是 Jira 建单（失败链路 + 评审链路）——自动评审本身没有定时任务。它只有两个入口：

- 页面 Run backfill 按钮 → POST /chatbi/events/report/review/backfill
- 保存规则时顺带跑 convertLegacyAutoNoPermission（只改判历史 NO_PERMISSION，不做新评审）

前端面板自己写着 Manual only / There is no background job and no nightly scan（ReviewRulesPanel.vue:351-362）。

数据对得上：AUTO 评审共 735 条，全部集中在 11-14（281 条）、11-15（454 条），最后一条 11-15 01:37:52，之后 0 条。

遗留列 auto_wrong_permission=t 在代码中 0 处引用（历史遗留，不影响行为）。

## 二、无权限轮次被结构性排除在自动评审候选集外

三态（CORRECT / WRONG / NOT_APPLICABLE）和“无权限不算错”都做了，但自动判 N/A 这条路径没写，于是无权限轮次永远只能人工标。

- 候选 SQL 写死排除（smartop-service/admin/src/main/java/com/lenovo/admin/chatbi/dao/ChatbiQuestionAutoReviewMapper.java:92）：

```sql
-- 无权限不是回答错误：环境/授权问题永远交给人工，绝不自动判 Wrong
AND NOT <LUDP_PERMISSION_SQL>
```

  注释原文即“绝不自动判”——当初有意定的口径（授权/环境问题不该由机器下结论），代价是这类轮次永久挂 Pending。
- 判定方式必须回查 agent 审计（同文件 :448 的 LUDP_PERMISSION_SQL）：execute_compiled_query / execute_sql 的 output_summary 匹配 "reason":"ludp_permission_denied"。这类轮次在事件表里仍记 status=success（agent 只负责解释“没有权限”），只看 failed_step 永远认不出来。
- 审计会话关联 AUDIT_SESSION_ID_SQL（同文件 :411）：优先 properties->>upstream_session_id（AskPreview 的 Spark 真实会话），否则回退 session_id；turn 标识取 query_id，老数据回退 properties.query_id。
- 最终结果口径 FINAL_SUCCESS_SQL（同文件 :462）：status/answer_status=success 或前端已渲染结果卡即算成功。理由：知识问答、PBI 推荐本来就不渲染结果卡，不能把“没看到卡”全判失败；反过来 status=failed 但已有成功结果卡（如 finalize 失败）算成功。
- 历史改判只针对旧规则产物：ChatbiQuestionAutoReviewMapper.java:117-129 要求 status=WRONG AND attribution_tag=NO_PERMISSION 才改成 NOT_APPLICABLE，人工结论一律不动（因为 NO_PERMISSION 现在也是 NA 的合法原因）。服务侧入口 ChatbiQuestionAutoReviewService.java:66,100。
- 枚举口径：ChatbiQuestionReviewService.java:30-54，NA_REASONS={NO_PERMISSION, OUT_OF_SCOPE}；NO_PERMISSION 只为兼容历史行保留，前端已移出 Wrong 下拉。Accuracy Rate = CORRECT / (CORRECT + WRONG)，未评审与 NOT_APPLICABLE 都不进分母（同文件 :20）。ChatbiReviewJiraCreator.java:172、ChatbiReviewJiraService.java:20：NOT_APPLICABLE 不算缺陷，永不建单。
