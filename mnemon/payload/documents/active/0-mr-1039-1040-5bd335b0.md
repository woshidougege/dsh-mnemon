# 筛选下拉计数口径统一：固定枚举全列展示 + 0 条置灰（MR !1039 / !1040）

本文件承接 **bb23dcc6-51fa-4326-866a-cd69c6d75e00**（《ChatBI 用户日志报表：筛选下拉显示可筛条数》）的前端口径部分：那份文档记录的做法是 `onlyWithData()` 先滤掉 0 条再拼数字；**本次改动把前端口径反转为「固定枚举全列展示、0 条置灰、人名类不置灰」，并删除 `withCount` / `onlyWithData`**。后端计数下发方式不变，仍以 bb23dcc6 为准。

## 1. 目标口径

- **固定枚举维度**（Rating / Final result / Band / Team / Page / Jira status / Review status / Review tag / Review source / Reason / Type / L3-L5 / Data scope）：选项**全列展示**，条数为 0 的项**置灰（disabled）**。
- **人名类维度**（User / Reviewer）：不是固定枚举，**不置灰**，只列有数据的人。
- 数据未返回时**既不置灰也不显示数字**，避免下拉先闪一排灰。

## 2. 改动落点（2 文件，+32/−47）

- `src/views/Setting/reports/user-logs/components/FilterBar.vue`
  - 沿用该文件已有的 `decorated()`（枚举全列 + `disabled: count === 0`）。
  - Rating / Final result / Band / Team / Page / Jira status / Review status / Review tag / Review source 全部改走 `decorated`。
  - 删除旧函数 `withCount`、`onlyWithData`。
  - 选项渲染结构：`<el-option :disabled="item.disabled">` 内 `span.ulr-opt-label` + `span.ulr-opt-count`（`v-if="item.count != null"`）。
- `src/views/Setting/reports/usage-issue-feedback/index.vue`
  - `withReviewCounts` 不再过滤 0，改为置灰；Reason、Jira status 一并补上计数与置灰。
  - Jira status 选项来源 `JIRA_STATUS_FILTERS.filter(item => item.value)`（`@/views/UsageIssueFeedback/jiraStatusFilters`），副标签走 `facetCount('jira', option.value)`。

## 3. 关键坑：`NaN === 0` 为 false

`decorated` 原实现是 `num(counts[value])`。后端没返回该 key 时 `num()` 得到 `NaN`，而 `NaN === 0` 是 `false`，于是「0 条」的项**不置灰**——Jira 的 `Creation failed` 就是这样漏掉的。必须写成 `num(...) || 0`。

同文件其他 num 用法（作为对照，均在 `FilterBar.vue`）：`:104 const count = num(counts[item.value])`、`:132 if (!keys.length) return num(counts[fallbackKey])`、`:133 return keys.reduce((sum, key) => sum + num(counts[key]), 0)`、`:448 return { ...item, count: num(count) }`、`:561 const execMax = num(filters.executiveMaxLevel) || num(org?.executiveMaxLevel) || 4`。
