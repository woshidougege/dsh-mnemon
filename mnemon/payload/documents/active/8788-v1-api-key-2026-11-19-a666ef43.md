# 8788 网关多客户端接入契约：谁要 /v1、用哪个 key、哪些不能动

调查时间 2026-11-19。前提：本机 `http://localhost:8788` 的后端已从 HUB（Python 便携版）换成 PANEL（Go 单二进制 `wb2api.exe`）。迁移过程、脚本化切换时间线与网关自身的路由契约见 `f5b4ff78-df14-4128-80a7-c44d0f18f07b`；HUB/PANEL 检索通道差异见 `a33b2a00-83e9-4029-b9c7-ac52472c9708`。本文只记录**切换后各客户端如何接入**这一层，因为用户反馈「好多地方的配置都没写 `/v1`」。

## 1. 触发问题

切换后 DSH 之所以没有断，是因为它的 `baseURL` 已经写成 `http://localhost:8788/v1`。但本机上还有多个工具指向 8788，其中多数写的是裸地址；PANEL 与 HUB 对裸路径的处理不同，于是这批配置全部失效。

## 2. PANEL 实测兼容矩阵（127.0.0.1:8788）

| 路径 | 结果 |
|---|---|
| `/v1/chat/completions`、`/v1/responses`、`/v1/models`、`/v1/search`、`/v1/fetch` | 200 |
| `/chat/completions`、`/responses`、`/models`、`/search`、`/fetch`、`/embeddings` | 404 |
| `/messages` 与 `/v1/messages` | 均 200 |
| `/v1/v1/messages`（客户端自己补了一次 /v1 之后再拼） | 404 |

结论：PANEL **只**为 Claude Code 的 `/messages` 做了裸路径兼容，其余端点一律要求 `/v1`。因此**不存在一个统一改法**——有些客户端会自己补 `/v1`，给它们的 baseURL 加了就会变成双前缀 404。

## 4. token 是第二个独立问题（不是路径问题）

HUB 支持多 key，PANEL **只认一个 `api_key`**。实测：

```
x-api-key: <Claude Code 里的旧 token>   => 401
Bearer      <Claude Code 里的旧 token>   => 401
Bearer      <WORK_BUDDY_API_KEY 的值>    => 200
```

所以 `~/.claude/settings.json` 里即使路径正确（不能用 /v1），也必须把 `ANTHROPIC_AUTH_TOKEN` 换成 `WORK_BUDDY_API_KEY` 的值，否则仍然 401。（具体 token 值不入文档，取值见环境变量。）

## 5. 模型 id：裸名的「cn 默认域兜底」规则

`/v1/models` 返回 49 个模型，**全部带域前缀**（`cn:` 国内号池 / `global:` 国际号池）。裸名实测：

| model | 结果 |
|---|---|
| `deepseek-v4.1-flash` | 200 |
| `mimo-v2.6-pro` | 200 |
| `kimi-k3.1-pro` | 200 |
| `deepseek-v4.1-flash-sg` | 400 |
| `gpt-6.2-astra` | 400 |

规则：裸名按 **cn** 域兜底解析，所以 cn 域模型不写前缀也能跑；global 独有的模型裸名直接 400，必须写 `global:`。最稳做法是照抄 `/v1/models` 返回的 id。

## 6. 曾评估但未采用的方案：8788 挂一层兼容代理

思路：PANEL 挪到内部 8790，8788 上放一个薄代理，同时做两件事——裸 API 路径自动补 `/v1`（`/v1/*` 原样透传，避免双前缀）、把旧 key 映射成当前 `api_key`。这样全部客户端一字不改，Claude Code 的 token 问题也一并消掉，代价是多一个常驻 Node 进程。

最终用户选择自己逐处加 `/v1`（方案 B），所以**这层代理没有实现**。保留此条的理由：一旦将来接入的客户端继续变多、或又出现「某些工具自己补 /v1」的冲突，这条路仍是最省事的收敛点，届时可先起在别的端口验通再按脚本方式切换、失败自动回滚。
