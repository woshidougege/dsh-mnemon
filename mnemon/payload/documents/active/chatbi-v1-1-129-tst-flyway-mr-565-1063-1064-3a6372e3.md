## 2. 环境现状与 tst 清理（checksum 一致性）

合并迁移的代价：tst 已跑过旧结构与旧 1.1.130，重启会报 `Migration checksum mismatch for 1.1.129`。

清理前的实测：
- 生产 flyway 停在 `1.1.127`，预发/生产均无 `ssg_chatbi_auto_review_rule`（`relation "public.ssg_chatbi_auto_review_rule" does not exist`）；
- tst：`1.1.128 Extend service portfolio config`（checksum 1682998329）、`1.1.129 Create chatbi auto review rule`（checksum 1674475902，旧结构）、`1.1.130 Rework chatbi auto review rule`（checksum -730156209，13:38 刚跑），表内 `rows=0`；
- 权限：表 owner 是 `a_appconnect`，`p_renxp4` 实测 `can_delete=f`（无 DELETE 权限），因此本次必须申请服务账号，已按规范先报环境/原因/语句并获用户"可以"授权。

执行（tst `10.62.79.148:5432/ssg_ops_agent`，`a_appconnect`，用完即断）：
```sql
DROP TABLE IF EXISTS public.ssg_chatbi_auto_review_rule;
DELETE FROM public.flyway_schema_history WHERE version IN ('1.1.129','1.1.130');
```
结果：`flyway rows deleted=2`、表已不存在，tst 当前最新迁移回到 `1.1.128`。后续：用户重启后端 → flyway 用新 `V1.1.129` 建表 → 规则页是空表（`No rules yet`），需点 `Add suggested (14)` 生成可用规则（空表=不自动评审是既有口径）。

教训：未上生产的迁移一旦改结构，直接改原迁移文件 + 清测试库 flyway 记录即可，不要新增"补偿/重建"迁移。

## 4. 导入导出方案（提案：导出可选「只导评审」，导入批量回写）

### 现状
导出只用于"往外给"：query 页签导出多工作表（会话明细 / 反馈明细 / 埋点原始事件），会话明细 27 列，不适合改了再传回来；系统没有导入。`ChatbiEventExportService.java` 里 `FEEDBACK_LIST_HEADERS` 与各列索引常量（`FEEDBACK_LIST_TYPE_COLUMN`、`FEEDBACK_LIST_JIRA_LINK_COLUMN` 等）是反馈列定义；query/feedback 已改为按筛选条件全量流式生成（不再传 `page`/`size`），只产 xlsx；raw 仍保留「当前页 / 全部数据」。

### 导出侧
在通用导出弹窗加 `Export type`：`Full report`（默认，行为不变）/ `Review only`（新，单 sheet 10 列）。只对 query、feedback 页签出现（raw 无评审语义）。

评审模板列：A `Session ID`、B `Turn key`（主键，导入定位，标灰不可改）；C–G `Time`/`User`/`Question`/`Final result`/`Failure category`（只读参考）；H `Review status`（Correct / Wrong / Not applicable / 留空）、I `Attribution tag`（N/A 时填原因）、J `Remark` 可改；第二 sheet 放说明 + 可选值清单。

### 导入侧
- 筛选条右侧 `Import review` 按钮 → 选 xlsx 上传 → 结果弹窗 `Updated 128 · Skipped 12 · Failed 3`，失败给行号+原因（如 `第 N 行：Attribution tag is required when status is Wrong`）。
- 逐行校验与抽屉保存同一套规则（Wrong 必带归因、N/A 必带原因、Correct 清归因），避免两套口径。
- 写库复用同一 `save()`：`review_source=HUMAN`、记 append-only 流水、reviewer 取当前登录人。
- 表头**按名字匹配不按列序**（可插自定义列、可调顺序）；单次限 2000 行；分批事务，部分失败不影响成功行。

### 待用户拍板的 4 点（含建议）
1. 模板默认导全部还是只导未评审 → 加 `Only pending`，**默认勾上**（建议）。
2. 导入判 Wrong 是否自动建 Jira 单 → **不建**（避免一次刷几百张单给 longyu3），要建则给勾选。
3. 已有结论是否覆盖 → 覆盖（人工优先），结果单列 `Overwritten`。
4. 先只做 query 页签 → 是（feedback 结构不同，后续镜像）。

改动面估算：后端新增 1 个 import service + 2 个端点（模板导出走现有导出接口加 `exportType` 参数）；前端 1 个导入弹窗 + 导出弹窗加单选框。
