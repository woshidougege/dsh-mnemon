# 回放翻译整会话第四迭代：按文本量切块 + 3 路并发

前序文档：`64041ba0-ab9a-437b-9926-14e657b5662e`（记录到「整会话按钮 + 四层分批 + 容量结论」为止）。本篇只记这次针对「翻得慢 / 翻完才显示」的修正与其交付。

## 用户反馈的现象（8 轮会话）

会话 `96658053-5ea0-4cce-8e6d-90ca7100e5d6 · eb3314e6-c625-4b5b-89ca-f2979818a955`，8 个提问：翻译不够快，且不是逐段出现，而是**全部翻完才一次性显示**。这与前一版宣称的「每批完成即生效」相矛盾，需要定位原因。

## 根因：按轮数分块在小会话退化成单块

前一版 `translateWholeSession()` 用 `const TURNS_PER_CHUNK = 20` 按轮数切块：

- 8 轮 < 20，整篇只切成 **1 块**；
- 这一块内部仍由前端按「12 段 / 8000 字符」切成十几批**串行**送模型；
- 所有批返回后才执行一次 `translations.value = { ...next }`，整篇一次性替换。

于是「每块即时生效」在单块场景下等于「全部完成才生效」，慢也慢在十几批串行 × 每批 3~5 秒 ≈ 30~40 秒。教训：**分块阈值应以文本量为基准，按轮数切会在短会话上退化**。

## 改法

- 从「按轮数切」改为**按文本量切**：累计到 ~8000 字符就切一块，单块最多 4 轮；8 个提问的会话约切成 5~7 块。
- 每块返回后立即 `translations.value = { ...next }` 落地，因此能看到一轮轮（按块）陆续变中文。
- **3 路并发**：串行改并发后总时长约为原来的 1/3。
- 只有真正写入译文的轮次才重建结果卡片——`props.translations` 引用未变的轮次不重渲染，避免整页闪烁。
- 保留前版语义：全局去重（同一句模板话术只付一次钱）、单块失败只影响该块（`failedChunks` + "N block(s) failed" 提示，不丢已完成结果）、语言切换后整篇完成态作废。

主要落点仍有 `translateWholeSession()`（`src/views/Setting/reports/history-replay/HistoryChatPanel.vue`，本次 diff 为 77 增 46 删）。
