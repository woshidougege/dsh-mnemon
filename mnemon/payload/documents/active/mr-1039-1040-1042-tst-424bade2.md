## 2. 设置页导航不自动折叠：master 与 develop 逻辑分叉

现象：生产 `https://ssgspark.lenovo.com/setting/settings` 进入后左侧导航保持展开，测试环境正常。

根因（`src/views/Setting/settings/components/SettingsNav.vue`）：

- master 旧逻辑只在**从未写过分区记录**时用 `defaultCollapsed`：
  ```ts
  const collapsed = computed(() =>
    storedChoice.value === null
      ? Boolean(props.defaultCollapsed) || narrow.value
      : storedChoice.value === '1',
  )
  ```
  用户点过展开 → `localStorage['settings-nav-collapsed'] = '0'` → 之后每次进设置页都读 ''0''，永远展开。
- develop 已改成"进入即收起、展开只对本轮生效"：`forceCollapsed = ref(Boolean(props.defaultCollapsed))`，`collapsed = forceCollapsed || (storedChoice === null ? narrow : storedChoice === '1')`；`toggleCollapsed()` 里先置 `forceCollapsed = false` 再写 localStorage。

结论：不是部署问题，是两条分支此文件逻辑不同；测试环境没点开过所以两边表现一致。

修复（!1042）：把 develop 的 `forceCollapsed` 语义同步到 master，只动 `SettingsNav.vue`；注释同步改成"每次进入设置页都先收成图标栏，点顶部按钮可在本次浏览中展开"。合并前的临时绕过：F12 → Application → Local Storage 删 `settings-nav-collapsed` 再刷新。

## 4. 两个环境坑

- **401 全量假故障**：首轮 12 个接口全部 401，原因是 Redis 里登录 token 换过一次（77 → 205 字符），旧 token 失效。重新登录取 `token` cookie 后全绿。遇到整体 401 先查 token 长度/时效，不要怀疑接口。
- **人名类下拉留白**：User 下拉里有用户无数字（Adam Partaledis、Dana Radosinska 等），是这些人在当前窗口内没有反馈、`userCounts` 无该 key；人名类设计上不置灰，因此留空而非显示 0。
