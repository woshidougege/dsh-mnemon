# ChatBI 问数自动评审规则（V1.1.121）+ 评审/评论导出

实施记录：SSG 问数（ChatBI）把「一眼能判定是错」的问数自动落成 Wrong，并把评审结论、评论纳入 Excel 导出。后端 1 支 MR、前端 2 支 MR，**均未合并**（2026-11-13 完成）。

## 1. 动因

人工评审只能覆盖少量抽查，Accuracy Rate 的分母长期偏小。目标：把可规则化的错判直接自动化，规则可配置，人工仍可覆盖。

## 2. 规则（Admin settings → Operations → Review rules）

前端 `ssg_sales_ops-wt-review-master/src/views/Setting/settings/panels/ReviewRulesPanel.vue`（保存/放弃用共享 discard dialog）。

- 一个总开关 + 三条规则，默认口径：
  1. **最终失败且没有结果卡** → Wrong，归因按失败步骤自动判定（Other / Wrong report / Definition mismatch / Display error）
  2. **LUDP 无权限** → Wrong · No permission
  3. **反问/待补充** → **默认关闭**：反问不一定是错，必须显式打开才判
- 只处理最近 **90 天**真实问数，排除 `backfill` 导入数据与巡检 probe。
- 保存后立即重建窗口内的自动结论；另有每小时兜底任务。

## 3. 落库与人工覆盖语义（关键设计）

- 自动结论写入 `ssg_chatbi_question_review`，`review_source=AUTO`，`reviewer_itcode=system:auto`、`reviewer_name=Auto rule`。
- 人工在任何页面保存 Correct/Wrong 都覆盖自动结论并转 `HUMAN`（之后不再被任务覆盖）。
- 人工「撤销」写抑制名单 `ssg_chatbi_question_review_dismissal`，任务不会把自动结论又插回来。
- 迁移 `V1.1.121`（新增 review_source 等列）需随部署由**应用账号**执行。

## 4. 导出改动（后端 `ChatbiEventExportService.java`）

- Sessions / Feedback details 新增 `Review source`、`Comments` 两列。
- 新增 **Review comments** Sheet：一条评论一行（问题、评审结论、归因、评审人、评论人、时间），行内 **Back** 跳回原表；原表 Comments 列显示 `Open comments (n)` 并跳转到对应评论行。
- 双向回链列索引：会话明细「用户问题」固定首列 A —— `sessionQuestionColumn()` = `CellReference.convertNumToColString(SESSION_QUESTION_COLUMN_INDEX)`；反馈明细的「返回问题」统一跳回 A 列（`cellLink(sheet, column, excelRow)` 生成 `'Sheet'!A12` 形式）。
- 评论批量读取 `loadCommentsForExport()`：按 500 个 session id 分片；缺表/权限异常只 `log.warn` 并降级为空，**不能拖垮整份导出**（异常分支直接 `return List.of()`，丢弃已累计批次）。
- 评论 key：`sessionId + "|#|" + turnKey` —— 不能用 `\\u0000` 拼接，javac 会把 unicode 转义当字符处理。
- 反馈列表 27 列，列宽数组与表头一一对应；外链只挂在 `FEEDBACK_LIST_JIRA_LINK_COLUMN = 18`（Jira ticket），其余位置空串表示无链接。
- 底色/标识：Review status 底色 Correct 绿、Wrong 红、Pending 黄、Auto 蓝；Review chip 只在「已评审的自动结论」上加 **AUTO** 角标；评审抽屉顶部显示 `Auto` + 时间，并提示保存后转人工、不再自动覆盖。
- 评审/归因文案集中在 `REVIEW_TAG_LABELS`（DEFINITION_MISMATCH→Definition mismatch、WRONG_REPORT、DATA_MISSING、NO_PERMISSION、DISPLAY_ERROR、OTHER），库里只存枚举值；归因只对 Wrong 显示，判对/待评审为 `—`。
